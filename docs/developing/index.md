# 开源发展现状与社区协作指南

企业在使用开源项目时，需要做好许可证合规审查、评估项目健康度、排查安全漏洞，也可以从活跃社区贡献者中发掘潜在人才。

开源项目天然具备开放透明的特性，信息可以被所有人自由获取，这是很多闭源项目很难做到的。闭源体系下信息往往经过层层审批，普通开发者很难拿到完整资料，想要参与项目改进更是门槛重重。

分布式协作是开源非常典型的工作模式，跨地域的大型团队可以在没有集中管控的前提下高效开展工作。
新兴社区和开源组织常常会遭受质疑、被严格监管，甚至面临诉讼风险，很多项目会因为外界对于新事物的排斥而被迫停止。

大部分人抗拒改变，根源来自对未知的恐惧。面对新技术、新工具、全新的工作流程与协作模式，能力上的暂时缺失，容易让人产生失去掌控感的焦虑情绪。

信任资源不足，是欠发达地区开源生态需要面对的现实难题。

## 发展中国家开发者面临的开源挑战

经济层面的压力是摆在发展中国家开源参与者面前最直观的障碍，从硬件设备到网络环境都会带来不小的影响。
高性能开发设备、稳定高速的网络，都会制约本地开发者参与开源贡献，可以借助 Watt Toolkit 等工具改善网络访问条件。

很多开发者一开始投入大量时间学习开源项目、提交贡献，当出现有偿工作机会之后，就不得不暂停开源活动。生存需求优先级更高，这是非常现实的选择。

社区需要通过运营活动、本地化文档建设，尽可能降低本地开发者的参与门槛。
英文是全球技术生态的通用语言，读懂源码、文档、架构方案与技术规范，是做出有效贡献的基础，借助开源资料同步提升英文能力是可行的学习路径。

## 社区支持方案

我们提供基础 GitHub 团队协作支持，缓解设备、网络条件不均，少数人长期垄断项目维护权的现状。
社区会通过运营推广、线下与线上活动、文档本地化等方式扶持本地开源建设。

我们鼓励成员将自己的开源贡献实现价值转化，任何对外开源项目的参与经历都值得被记录。
针对公司内部项目，在签署合规协议的前提下，鼓励参与者把项目信息同步到社区文档，吸引感兴趣的同事共同维护，实现透明共建。
开源可以带来规模效应，汇集全球开发者的力量，无论对于个人、企业还是区域技术生态，长期收益都大于潜在风险。

开源文化需要每一个人共同建设，尽可能在自己可以做到的范围内去推广开源理念，带动身边更多开发者参与进来。

## 开源项目与团队特征

- **全球性**：不受地域限制，任何人都可以申请参与项目
- **异步协作**：成员分属不同时区，不需要所有人同时在线工作
- **公开透明**：项目讨论、沟通记录对外可见，社区可以共同监督

## 平等友好沟通准则

社区优先采用低语境沟通方式，表达直接清晰、附带必要背景信息，降低跨文化理解成本。
官方沟通默认使用英文，即使语言表达不够流畅，所有参与者也应当保持包容友好。

沟通方式建议：

1. 一对一邮件沟通，可以参考对方过往的行文风格，适配高语境或低语境表达方式；无法判断对方习惯时，默认选择低语境，先简要说明背景，再直奔主题。
2. 面向全体社区发布公告、公开文档时，坚持低语境表达，文字简洁，避免冗长的铺垫，降低读者的阅读负担。
3. 沟通时优先做善意假设。高语境表达习惯的人可能表述比较委婉，低语境表达习惯的人风格会更加直白，沟通前先抛开固有偏见，聚焦对方实际想要传递的信息。
